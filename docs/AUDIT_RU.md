## Исправление доступности в 1.1.1

В версии 1.1.0 в `ProjectCommandAvailability.IsCommandAvailable` ошибочно использовалось `!doc.IsReadOnly`. В 1.1.1 callback проверяет только наличие проекта и отсутствие режима редактирования семейства. Временное состояние API не используется как условие отключения кнопок. Проверка `IsReadOnly` перед изменением документа сохранена в `RevitSupport.TryProject`. Ошибка выявлена по сообщению пользователя после установки 1.1.0; прежняя проверка метаданных DLL не могла её обнаружить. Динамическая природа IsReadOnly подтверждена установленной документацией Revit 2022 (RevitAPI.xml, Document.IsReadOnly) и [документацией Autodesk](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/7e813a1b-9163-2509-f280-82572598432b.htm).

## Панель и редактирование

- Команды привязаны к точным именам классов; поиск первого IExternalCommand через reflection удалён.
- DLL и иконки ищутся рядом с ARV_Ribbon.dll. Сбой одной кнопки не обрывает создание остальных; диагностика собирается в одно сообщение.
- Команды изменения проекта недоступны без подходящего открытого документа; добавлены проверки при прямом запуске через Add-In Manager.
- Окна привязаны к текущему окну Revit и центрируются средствами WPF, без смешивания экранных пикселей и DIP на мониторах с масштабированием.
- Создано общее решение Visual Studio; одинаковый ProjectGuid у HideCategory/HideSubCategory исправлен. Все проекты явно настроены на x64 и .NET Framework 4.8.
- Общие небольшие функции находятся в редактируемых `.cs` в src/Common и подключены как linked files. Отдельной вспомогательной DLL нет.
- Весь комплект имеет версию 1.1.1.0. Из текущего дерева удалены CreateCeil, FamilyContainerModel и ExportNavis; старые снимки остаются только в истории Git.

## Оставшиеся ограничения

- Чистовая отделка: по указанию владельца сохранено накопительное увеличение длины плинтуса при повторном запуске с ненулевым коэффициентом. Группировка и суммирование площадей также сохранены; их пересмотр отложен.
- Сопоставление стен с помещениями по ADSK_Группирование зависит от данных модели. В черновой отделке неоднозначные номера размещённых помещений приводят к явной ошибке вместо угадывания.
- «Виды на лист» использует заданный пользователем шаг. Автоматической упаковки по размерам, контроля пересечений и подбора места на листе нет.
- Обрезка работает по элементам, видимым в текущей области вида; элементы за существующей активной рамкой могут не входить в выборку API. Нераспознанные семейства обрыва не используются; при необходимости их имя нужно дополнить одним из указанных слов.
- Проверка в самом Revit не выполнена из-за тайм-аутов Windows Computer Use. Поведение с рабочими наборами, геометрией, шаблонами, спецификациями и проектными параметрами должно быть подтверждено на тестовой копии модели. Собранный пакет не устанавливался в систему в рамках этой работы.
