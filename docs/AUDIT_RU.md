## Обнаруженные проблемы

### Подтверждённая ошибка компиляции

`src/CreateCeil/Command.cs:148`: `BuiltInParameter.ROOM_BOUNDARY` отсутствует в установленном API Revit 2022. Компилятор выдаёт CS0117. Проект исключён из обычной сборки, исходный код сохранён без исправлений.

Дополнительно в этом проекте используется только `segments[0]`: внутренние контуры помещения не учитываются (`Command.cs:137`). Высота берётся из `room.LimitOffset`, который сам по себе не выражает полную высоту помещения между разными уровнями (`Command.cs:153`). Эти алгоритмы требуют отдельной доработки и проверки на моделях.

### Ошибки и ограничения, видимые по коду

- `src/CreateViewsForWorksets/WorksetViewsCommand.cs`: имя вида всегда `РН_{ws.Name}`, существующие имена не проверяются. Повторный запуск при сохранённых видах с такими именами приводит к конфликту и откату транзакции. Доступ к активному документу выполняется до `try`; нет проверки совместной работы.
- `src/PlaceViewsOnSheet/PlaceViewsCommand.cs`: принимается любой выбранный `View`, кроме листов и шаблонов; нет `Viewport.CanAddViewToSheet`. Спецификации требуют другого способа размещения, уже размещённые и неподходящие виды могут сорвать общую транзакцию. Сообщение об успехе использует количество выбранных видов.
- `src/ViewNumberingPlugin/Command.cs`: временные номера `_TMP_i` не проверяются на совпадение с невыбранными видовыми окнами. Финальные номера тоже могут конфликтовать с невыбранными окнами листа. Буквенная нумерация за пределами массива возвращает `ERR_...`, а не продолжение алфавита. В диалоге объявлены 4 строки Grid, кнопки назначены в строку 4 (пятую): возможное наложение с полем ввода, требуется визуальная проверка.
- `src/FamilyContainerModel/MainWindow.xaml.cs:213`: изменения модели запускаются через `Task.Run` и `Dispatcher.Invoke`, а не через Revit `ExternalEvent`. Возврат на UI-поток сам по себе не гарантирует допустимый контекст API. Размещается только первый тип каждого семейства, используется один способ создания экземпляров без обработки семейств, требующих основу. Это кандидат на доработку, а не проверенный готовый инструмент.
- `src/HideCategory/StartClassPlugin.cs` и `src/HideSubCategory/StartClassPlugin.cs`: команды меняют все подходящие виды и шаблоны. При снятии шаблона с вида восстановление не защищено `finally`; в HideCategory исключение может быть проглочено с последующим общим `Commit`, оставив вид без исходного шаблона. Для обеих команд нужна проверка на копии модели с шаблонами.
- `src/CopyViewsWithRename/CopyViewsCommand.cs`: после `Duplicate` переименование выполняется без отдельной под-транзакции. Если переименование упадёт, исключение запишется в список, но уже созданный дубликат может остаться после общего `Commit`.
- `src/ARV_Ribbon/Class1.cs`: фиксированный путь DLL; поиск первого `IExternalCommand` через reflection; исключение в создании кнопки может прервать добавление остальных панелей, при этом `OnStartup` всё равно возвращает `Succeeded`. Загрузка иконок молча подавляет ошибки. Это снижает надёжность диагностики, но не доказывает неисправность текущего установленного набора.

Эти пункты основаны на исходниках. Поведение команд в живом Revit в рамках этого аудита не проверялось; результаты расчётов отделки и геометрической обрезки требуют модельных примеров.
