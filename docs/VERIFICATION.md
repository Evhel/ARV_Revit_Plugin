# Проверка выпуска 1.5.0

- 15 проектов собраны через build.ps1 без ошибок и предупреждений.
- 78 проверок общих алгоритмов и нижней границы, 39 проверок вспомогательной логики переноса (9 порядка видов, 15 сохранения оформления, 15 горизонтальных/внутривидовых смещений) пройдены без запуска Revit.
- Четыре файла ядра переноса совпадают побайтно с отдельным проектом 1.0.20: [происхождение и SHA-256](origin-source-provenance.json).
- 8 сценариев расчёта центра рабочей области: смещённые и отрицательные координаты мониторов, разные размеры в экранных координатах, слишком большое окно. Для тринадцати окон проверено отсутствие конфликтующего CenterOwner/CenterScreen. Дополнительно проверен реальный Win32-перенос скрытого тестового окна в центр монитора при сдвинутом вниз скрытом владельце. Тест не использует окно Revit; его фактическое положение пользователь проверяет вручную.
- Загружены тринадцать рабочих компоновок WPF; обработчики сверены с собранными классами. 52 рендера при 100/125/150/200%, тринадцать маленьких окон с ошибкой; нижние кнопки доступны. Для переноса подтверждено сохранение безопасного действия по умолчанию «Отмена».
- Проверены реальные конструкторы окон нумерации, копирования, размещения и переноса без доступа к документу. Проверены ошибки ввода, переключение замены текста и значения сводки переноса.
- SVG и PNG иконок переноса и смены основ армирования сохранены, PNG: 32×32 RGBA, прозрачный внешний фон, около 96 DPI; проверены поля и вид на трёх фонах.
- Все 15 DLL: версия 1.5.0.0, x64, Revit API 22. Проверены 15 привязок кнопка → DLL → класс → availability → PNG и манифест.
- 33 файла ZIP сопоставлены с пакетом по SHA-256; проверена контрольная сумма самого ZIP. Исключённые команды, SelfTest и диагностические типы не входят в производственную сборку переноса; библиотеки Autodesk и тестовые DLL отсутствуют в поставке.

[Метаданные](release-verification.json), [контрольные суммы](../dist/Revit2022/SHA256SUMS.txt), [перенос и ручная проверка](ORIGIN_RELOCATOR_RU.md), [правила центрирования](design/UI_STYLE_RU.md).

Команды, фактическое центрирование и переключение DPI в Revit пользователь проверяет вручную. Revit не запускался, управление им не использовалось, установка и модель не менялись. Рендеры используют демонстрационные данные и не проверяют изменение модели. Полный перенос проекта в составе панели ещё требует ручной проверки.

## Исправления 1.4.1

- Уникальные внутренние имена всех 14 кнопок включают DLL и класс команды; проверка пакета отклоняет повтор имени. Две команды армирования больше не используют одно имя DLL в качестве имени кнопки.
- Настройки активности слоёв восстанавливаются до остальных параметров. Поля соответствия слоёв обрабатываются последними. Отказ Set без исключения откладывается до следующего прохода после Regenerate; принимается только фактически совпавшее значение. Окончательная проверка параметров и откат отдельной зоны сохранены.
- 12 сценариев компилируют рабочий ParameterValue.cs с ограниченными двойниками API: четыре поля соответствия в состояниях 0/1, повтор записи зависимого поля, снятие read-only после регенерации, постоянный отказ записи и несовпадение возвращённого флага с фактическим значением. Это проверка нашего кода, а не подтверждение поведения API на модели.
- Для одного результата — карточка 620×380 DIP с переносом текста причины; для нескольких — таблица высотой по числу строк. Реальные конструкторы одиночного и двухстрочного отчёта проверены; одиночная ошибка отрисована на четырёх DPI дополнительно к 44 общим рендерам.

## Новые команды армирования

Проверены два класса IExternalCommand в новой DLL и их отдельные привязки. Пересоздание на реальной стене, перенос параметров/линий и удаление старых зависимостей в Revit не выполнялись. Для ручной проверки: [инструкция армирования](AREA_REINFORCEMENT_HOSTS_RU.md).

## Изменения 1.4.2

Проверены сборка двух команд с новыми подписями, API 22: PickObjects с фильтром зон, получение Level.Name из WALL_BASE_CONSTRAINT, локальный IFailuresPreprocessor. Существующий алгоритм поиска нижней границы не изменён. Успешный одиночный результат не открывает отчёт; массовый всегда показывает отчёт с базовым уровнем.

8 проверок с двойниками API проверяют рабочий обработчик предупреждений и извлечённый из Commands.cs рабочий фильтр выбора. Только заданное предупреждение удаляется; другое предупреждение и ошибка того же типа сохраняются. Это не тест интерфейса выбора и не обработка транзакции в настоящем Revit.

## Исправление 1.4.3

Причина 134 из 148 пропусков в предоставленном отчёте — попытка копировать четыре системных признака сравнения слоёв. Они исключены из снимка переносимых параметров по BuiltInParameter, а не по локализованному имени. Отказы записи остальных параметров по-прежнему завершаются откатом зоны. Геометрический поиск стен не изменён.

Обновлены проверки ParameterValue.cs с двойниками API: всего 20 сценариев. Все четыре признака в состояниях 0/1 отказывают в Set и остаются отличными от исходных даже после Regenerate. Проверяется отсутствие обращений к их Set, сохранение действительных Double/ElementId/Integer настроек и отказ Verify при изменении действительного шага. Прежние сценарии отложенной записи, разблокировки, постоянного отказа и проверки фактического значения сохранены. Это проверка нашего кода, не тест реального API Revit; прежняя гипотеза теста о пересчёте признаков удалена.

## Итоги 1.4.4

Единый статус для необработанной зоны — «Пропущено». В отчёте отфильтрованы успешные зоны; сводка считает весь входной список. Реальные конструкторы отчёта проверяют один пропуск, два пропуска, смешанный результат (один успех и два пропуска), смешанный результат с одной карточкой и полный успех без строк. Проверка выполняется без запуска Revit.
