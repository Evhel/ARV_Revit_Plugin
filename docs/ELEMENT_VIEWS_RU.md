# Создать виды элемента — 1.5.4

Кнопка: **ARV → Виды → Создать виды элемента**. [Редактируемый проект Visual Studio](../src/ElementViews/ElementViews.csproj).

## Настройки видов

1. Выберите элементы перед запуском либо по предложению команды. Esc отменяет выбор. Связи и объекты без модельных габаритов не обрабатываются.
2. В строке «Один экземпляр на заполненное значение параметра» выберите параметр из списка или начните вводить его название. Работает автодополнение начала названия; уникальное вхождение введённого текста также распознаётся при запуске. Неоднозначное название нужно выбрать из списка. При снятой галочке строка серая, поле недоступно; ранее выбранный параметр сохраняется для названий.
3. При включённом отборе пустые/отсутствующие значения исключаются. Для каждой марки выбирается нижний экземпляр (минимальная Z габаритов), затем левый (минимальная X), затем верхний на плане (максимальная Y), затем меньший ID. Координаты проекта. Без отбора обрабатываются все элементы. Строки сравниваются с учётом регистра после удаления крайних пробелов, числа и ссылки — по хранимым значениям.
4. В компактной таблице отметьте нужные виды: до трёх планов и четыре боковых разреза. Номера строк постоянные: 1–3 планы, 4 спереди, 5 сзади, 6 слева, 7 справа. Отметка плана — мм от низа габаритов элемента. Все виды, включая планы, создаются настоящими ViewSection.
5. Для каждой строки задайте префикс и суффикс имени. Название = префикс + значение выбранного параметра/порядковый номер + суффикс. Префикс по умолчанию `КЖ3_Арм_Пилон_`. В примерах интерфейса используется **Пм-1**; реальные номера без параметра остаются 1, 2, 3…
6. Столбец «Суффикс заголовка» заполняет параметр Revit **«Заголовок на листе»**: введённый текст + пробел + значение выбранного параметра. Например, `Разрез` и `Пм-1` дают `Разрез Пм-1`. Пустой текст оставляет только значение/номер. Это отдельная настройка от суффикса имени вида.
7. Шаблон каждого включённого вида обязателен. Доступны шаблоны разрезов. Масштаб берётся только из шаблона; назначенный ViewTemplateId и масштаб проверяются после регенерации. Шаблон, отключающий границы вида, вызывает пропуск комплекта.
8. В каждой строке таблицы задайте собственные отступы в группе «Отступы до границ вида»: «в стороны», «вверх», «вниз». Все значения в мм, допустим ноль. Для планов вверх/вниз соответствуют верхней и нижней стороне изображения горизонтального разреза. Тип видового экрана выбирается в строке; «По умолчанию проекта» сохраняет штатный тип.

## Схема листа

На вкладке «Листы» включите создание листа для каждого элемента, выберите семейство и тип основной надписи, задайте префикс/суффикс имени листа.

Без схемы виды размещаются автоматически слева направо с переносом строки. Чтобы задать собственное размещение:

1. Включите «Размещать по схеме листа».
2. Выберите число строк и столбцов, от 1 до 4.
3. Впишите в ячейки номера видов из таблицы. Каждый включённый вид должен встретиться ровно один раз. Пустые ячейки оставляют свободное место. Повторные, выключенные и пропущенные номера отклоняются до изменения модели.
4. «Заполнить по порядку» заполняет ячейки включёнными видами в порядке таблицы. Для ручного порядка, например, `7 | 4 | 1` даст справа/спереди/план 1 в верхнем ряду, а пустой второй ряд останется свободным.

Номера в схеме задают взаимный порядок по содержимому. Внутри столбца виды располагаются сверху вниз с общей вертикальной осью рамок экранов. Ширина столбца определяется его самым широким экраном с учётом штатного заголовка. Следующий столбец начинается справа с заданным зазором. Пустые ячейки и полностью пустые столбцы не резервируют место.

Пример `1 | 7 | пусто` в верхнем ряду и `4 | пусто | пусто` в нижнем: вид 4 находится непосредственно под видом 1 с той же осью X, вид 7 справа. Верхние виды столбцов выровнены по верхнему габариту. Нижние виды разных столбцов могут находиться на разных отметках: высоты экранов различаются.

**Слева, мм**, **Сверху, мм** и **Зазор между видами, мм** задаются пользователем; по умолчанию 20, 20 и 10 мм. Зазор применяется между соседними видами по вертикали и между столбцами. Габариты включают штатные заголовки; горизонтальные габариты симметрично дополняются относительно центра рамки, чтобы сохранить общую ось даже при несимметричном заголовке. Размеры измеряются в бумажных единицах после применения шаблона и типа экрана. Допустим нулевой зазор.

Начало компоновки привязано к указанным левому и верхнему полям. Справа остаётся контрольное поле 20 мм, снизу — 55 мм. Контур основной надписи внизу справа на схеме условный и не повторяет геометрию выбранного семейства. Значения левого и верхнего полей подписаны на схеме и обновляются при вводе. Размеры видов на схеме условные.

**При размещении по схеме большие виды не переносятся в отдельное место из-за размера ячейки.** Компоновка сохраняется целиком, даже если выходит за полезную область листа; итог сообщает количество таких видов. Для исправления можно изменить формат, шаблон или расположение. Масштаб автоматически не меняется. Без схемы остаётся автоматическая компоновка с переносом строки и сохранением не поместившихся видов справа за листом.

Отдельный TextNote с именем вида не создаётся. Положение и вид штатного заголовка задаёт выбранный тип экрана, команда его отдельно не передвигает. Чтобы видеть заполненный «Заголовок на листе», используйте тип с соответствующей подписью.

## Формат листа A/x

Под выбором семейства основной надписи находится строка **«Формат листа: А[ ]х[ ]»**. Поля передаются параметрам с точными именами латинская `A` и строчная латинская `x`. Пустое поле сохраняет значение семейства.

Сначала ищется параметр созданного листа, затем — его экземпляра основной надписи. Параметры типа не изменяются. Целочисленное поле принимает целое число; строковое — текст; Double записывается через Revit SetValueString с единицами проекта. Отсутствующий, неоднозначный, неподдерживаемый или недоступный для записи параметр вызывает объяснение в итогах: стадия создания листа откатывается, созданные виды сохраняются.

Формат задаётся до регенерации и измерения листа, чтобы компоновка учитывала фактический размер основной надписи. Влияние A/x на геометрию зависит от формул выбранного семейства.

## Настройки в файле

«Сохранить» и «Загрузить» записывают/читают JSON по выбранному пути. В файл входят A/x, индивидуальные отступы строк, поля листа, зазор, отбор, префиксы/суффиксы, заголовки, отметки, отступы, шаблоны, типы экранов, основная надпись и схема ячеек. Загружаются также файлы 1.5.1–1.5.3. Общие отступы из старых файлов переносятся в соответствующие строки; отступ планов — во все три поля планов. Для старых настроек A/x остаются пустыми. Для файлов 1.5.1/1.5.2 поля слева/сверху и зазор принимаются 20/20/10 мм. Схема из 1.5.2 сохраняет номера, но размещается по новой логике размеров.

В другом проекте ссылки сверяются по именам; чужой ID молча не назначается. Отсутствующий обязательный выбор или ошибочная активная схема вызывают сообщение без замены текущей формы.

## Геометрия и результат

Направления берутся из локальных осей семейства либо линии линейного элемента. Вертикаль боковых разрезов — Z проекта. Для наклонных элементов используются проекции осей на горизонтальную плоскость. При отсутствии осей применяются оси проекта с сообщением в окне. Соседние элементы остаются видимыми с учётом шаблона.

Низ — минимальная Z BoundingBox, границы рассчитаны по его восьми углам. Горизонтальные разрезы смотрят вниз с введённых отметок; отметка вне высоты элемента вызывает пропуск комплекта. Видимость обозначений на обычном разрезе зависит от настроек Revit и шаблона.

Запрещённые символы имени заменяются подчёркиванием, занятые имена дополняются `_2`, `_3` и далее. Названия длиннее 240 символов отклоняются. Номера листов — первый свободный ARV-0001 и далее. Существующие виды не переименовываются.

Ошибка вида/шаблона/записи заголовка откатывает новые виды только этого элемента. Ошибка листа сохраняет виды; ошибка размещения сохраняет виды и лист. Итог содержит счётчики, пропуски и сохранённые комплекты, требующие внимания. Успешные комплекты отдельными строками не перечисляются.

Без Revit проверены сборка, 123 проверки алгоритмов и параметров (14 из них — ограниченные двойники API для кода A/x), WPF и файлы поставки. В модели пользователь вручную проверяет шаблоны, разрезы, «Заголовок на листе», выбранные типы экранов и компоновку. Revit в этом выпуске не запускался.
