# Создать виды элемента — 1.5.1

Кнопка: **ARV → Виды → Создать виды элемента**. Исходники: [проект Visual Studio](../src/ElementViews/ElementViews.csproj), [команда](../src/ElementViews/Command.cs), [настройки окна](../src/ElementViews/MainWindow.xaml), [создание видов/листов](../src/ElementViews/ViewCreationService.cs), [математика отбора и разрезов](../src/ElementViews/ElementViewMath.cs).

## Как пользоваться

1. Выберите элементы модели и нажмите кнопку. Если подходящих элементов заранее нет, команда предлагает выбрать их и нажать «Готово». Esc отменяет выбор. Объекты связей, типы и объекты без модельных габаритов не обрабатываются.
2. Выберите параметр для названий: доступны параметры экземпляров и типов выбранных объектов. Показаны название и источник (тип/экземпляр), без ID. Без параметра используются номера 1, 2, 3… в порядке обработки.
3. При необходимости включите «Учитывать только один экземпляр…». Для каждого заполненного значения останется один элемент: минимальная Z низа габаритов, затем минимальный X левого края, затем максимальный Y верхнего края, при совпадении — меньший ID. Направления сортировки заданы координатами проекта. Текст сравнивается с учётом регистра после удаления пробелов по краям; числа — по хранимому значению, ссылки на элементы — по ID. Округление отображаемого значения и одинаковое имя разных типов не объединяют разные значения. При включённом отборе пустые/отсутствующие значения полностью исключаются; без отбора обрабатываются все элементы.
4. Отметьте нужные виды: три плана, спереди, сзади, слева, справа. Для планов введите смещения **в мм от низа элемента**. Для каждого вида задайте префикс и суффикс; между ними всегда остаётся значение выбранного параметра либо номер. Префикс по умолчанию — `КЖ3_Арм_Пилон_`. Выберите строку и задайте её префикс/суффикс под таблицей; рядом показан пример. Параметр можно использовать в названии при выключенном отборе.
5. Выберите обязательный шаблон для каждого включённого вида. Поскольку все виды — разрезы, доступны шаблоны разрезов. Масштаб берётся только из шаблона. Команда проверяет ViewTemplateId после назначения/регенерации и перед подтверждением комплекта. Ручного масштаба нет. Отступы разрезов задаются отдельно по бокам, сверху и снизу; для планов — отдельный одинаковый отступ со всех сторон. Все значения — мм.
6. Чтобы получить отдельный лист для каждого элемента, включите создание листов, выберите семейство **и тип** основной надписи, задайте префикс и суффикс названия листа. Без загруженных основных надписей можно создать только виды.
7. Нажмите «Создать». Итог содержит счётчики, число отфильтрованных повторов и только пропущенные элементы с причинами. Исходные элементы не изменяются.

## Ориентация и границы

- Для семейства направления берутся из его локальных осей. Для стен/балок и других элементов с LocationCurve локальная X направлена вдоль линии элемента. «Спереди» смотрит вдоль локальной +Y, «сзади» — −Y, «справа» — −X, «слева» — +X. Для повёрнутой колонны виды поворачиваются вместе с её осями.
- Боковые виды вертикальны по Z проекта; для наклонных элементов используются проекции локальных осей на горизонтальную плоскость. Если подходящих осей нет, используются оси проекта; это указано до создания в заголовке окна.
- Боковые разрезы располагаются снаружи габаритов элемента и показывают его целиком. Соседние элементы внутри границ/глубины вида остаются видимыми; результат также зависит от выбранного шаблона, фаз, категорий и других настроек вида.
- «Планы» — настоящие горизонтальные разрезы, смотрящие вниз, на заданных отметках. Это не ViewPlan и не детализация. Их обозначения можно показывать на обычных разрезах и перемещать вручную. Видимость обозначений зависит от настроек исходного вида и типа разреза (категории, масштаб, границы и шаблон).
- Низ элемента — минимальная Z его модельного BoundingBox. Границы создаются по восьми углам габаритов с отступом; для сложных форм они могут быть свободнее фактической геометрии. Отметка плана вне диапазона высоты элемента приводит к пропуску его комплекта с объяснением.

## Названия и листы

Названия видов: префикс + значение/номер + суффикс. Запрещённые символы заменяются подчёркиванием, совпадение с существующим названием дополняется `_2`, `_3` и т. д. Ничего существующего не переименовывается. Слишком длинное название (более 240 символов) не обрезается с потерей марки, а даёт ошибку. Повторный запуск создаёт новый комплект с новыми именами.

Лист: выбранная основная надпись, название по тому же конструктору, первый свободный номер ARV-0001 и далее. Виды размещаются слева направо с переносом строки, в порядке строк настройки. Учитываются размеры видов и их подписей. Поля: 20 мм сверху/слева/справа, 55 мм снизу под основную надпись, промежуток 10 мм. Для нестандартной надписи компоновку может потребоваться поправить вручную. Не поместившиеся виды сохраняются справа за границей листа для ручной компоновки. Масштаб шаблона автоматически не изменяется.

Ошибка создания вида или шаблона откатывает новые виды этого элемента. Ошибка создания листа сохраняет виды, ошибка размещения сохраняет виды и созданный лист. Прочие элементы продолжают обрабатываться. Создание сборок и изменение исходной модели не выполняются.

## Что проверить вручную в Revit

- 50 колонн / 17 марок: осталось 17 экземпляров; выбран нижний, затем левый/верхний по координатам проекта. При выключенном отборе обрабатываются все 50. При включённом отборе пустые марки исключаются.
- Повёрнутая и зеркальная колонна: направления четырёх боковых видов; три горизонтальных разреза на введённых отметках; их обозначения на обычном разрезе.
- Отдельные шаблоны, в том числе контролирующие масштаб; отсутствие скрытия соседей со стороны команды. Параметры видимости шаблонов пользователь проверяет самостоятельно.
- Названия с марками, без параметра, с повторными марками и при повторном запуске; листы с нужной основной надписью и свободными номерами.
- Размещение без пересечений, слишком маленький лист, неверная отметка плана: сохранение не поместившихся видов за листом; откат комплекта при неверной отметке. Отмена Esc/«Отмена» до создания, общий Undo после команды.

Собраны DLL API 22 и редактируемое решение. Проверены математика и WPF без запуска Revit. Создание видов, обозначения и листы на реальном проекте **ещё не проверены** — это выполняет пользователь.

## Настройки и подписи 1.5.1

Кнопки «Сохранить» и «Загрузить» записывают/читают JSON по выбранному пути. Сохраняются отбор, названия, отметки, отступы, шаблоны, типы экранов и лист. В другом проекте ссылки сверяются по именам; отсутствующий обязательный выбор выдаёт сообщение без замены текущей формы.

Тип видового экрана выбирается индивидуально в строке вида. «По умолчанию проекта» сохраняет штатный тип.

Опция названия над видом создаёт отдельный TextNote на листе, по центру над рамкой с отступом 5 мм, стандартным типом текста проекта. Он содержит полное имя вида. При последующем перемещении/переименовании вида текст нужно поправить вручную. Штатный заголовок экрана сохраняется; для исключения двойной подписи выберите тип без заголовка.

В итогах показаны счётчики, исключённые пустые значения, пропуски и сохранённые комплекты, требующие внимания. Успешные комплекты отдельными строками не перечисляются.
