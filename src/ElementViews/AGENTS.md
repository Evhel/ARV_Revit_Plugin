# Создать виды элемента

- Направления по локальным осям элемента в плане. Для семейства — GetTransform; для линейного элемента — направление его линии; при отсутствии осей явно сообщай о применении осей проекта. Вертикаль боковых видов — Z проекта.
- Все виды создаются ViewSection.CreateSection, включая три горизонтальных разреза на отметках от минимальной Z габаритов. Не заменяй их ViewPlan или Detail без нового запроса.
- Отбор одного экземпляра: минимальная Z габаритов, затем минимальный X, затем максимальный Y, затем ID. При включённом отборе пустые/отсутствующие значения исключай; без отбора сохраняй все элементы. Параметр можно использовать для названий без включения отбора.
- Соседние элементы остаются видимыми. Исходные элементы не скрывай, не перемещай и не включай в сборку.
- Шаблон каждого включённого вида обязателен. Передавай выбор по ID, проверяй ViewTemplateId после назначения/регенерации и перед Commit. Масштаб бери только из шаблона, ручного масштаба нет. Названия включают выбранное значение либо порядковый номер; занятые имена не переименовывай.
- Ошибка создания/шаблона откатывает новые виды элемента. Ошибка создания листа или размещения не откатывает уже созданные виды. Не поместившиеся экраны сохраняй за правой границей листа, сообщай об этом. Тип экрана выбирается для каждого вида. Не меняй масштаб ради размещения.
- Не создавай TextNote названия на листе. Применяй выбранный тип экрана. VIEW_DESCRIPTION = суффикс заголовка + пробел + значение параметра/номер. Примеры UI используют Пм-1; реальные номера без параметра остаются порядковыми.
- В схеме листа номера соответствуют постоянным номерам 1–7 строк видов. Каждый включённый вид должен быть указан один раз. Размещай по фактическим размерам: внутри столбца общая ось X рамок экранов, порядок сверху вниз с введённым зазором, ширина столбца по самому широкому экрану с подписью. Пустые ячейки не резервируют место. По схеме не перемещай большие виды за лист принудительно: сохраняй заданные отношения и сообщай о выходе за полезную область. Поля слева/сверху и зазор пользователя сохраняются в JSON. Схема и суффиксы заголовков входят в JSON.
- Настройки сохраняются/загружаются в JSON; ссылки проверяй по именам перед принятием ID, чужие ID из другого проекта не назначай молча. Ненайденные проектные ссылки оставляй пустыми и загружай остальные поля. Удаляй из схемы только номера ненайденных спецификаций. Не подставляй случайные аналоги. Повреждённый формат/неверные числовые значения по-прежнему отклоняй.
- Не запускай Revit и не подключайся к нему. Проверку в модели выполняет пользователь. Исходники, solution, DLL, инструкция и ZIP сохраняются в репозитории.

- Отступы задаются в каждой строке вида отдельно: в стороны/вверх/вниз в мм. Для горизонтального разреза вверх/вниз — стороны изображения по локальной Y вида. Старый JSON переносит общие отступы разрезов в строки разрезов, общий отступ планов — во все три поля строк планов.
- Формат листа: подтверждённые параметры экземпляра основной надписи «А» (U+0410) и «х» (U+0445). Ищи только в новых экземплярах основной надписи. Не используй латиницу, параметры листа или типа; не создавай копии типов. Пустое значение не меняет параметр. Диагностика семейства и её кнопка удалены по просьбе владельца.
- Для Double формата различай SpecTypeId.Number и измеряемые величины: число через Set(double), единицы разбирай UnitFormatUtils.TryParse. Проверяй фактическое значение после записи обоих полей и Regenerate; false из Set недостаточно для ошибки. При постоянном несовпадении сообщай введённое/полученное значения и тип, не подавляй отказ.

- Спецификации: 10 строк, источник выбирается с живым поиском по подстроке. Без Copy не дублируй и не меняй источник, фильтры и параметры. С Copy имя = исходное имя + _ + марка, с защитой от конфликтов. Пункт «Не менять фильтр» копирует спецификацию с сохранением всех фильтров и доступен по умолчанию. Незаполненный после загрузки фильтр отличается от этого явного пункта. При выборе фильтра меняй только выбранную существующую строку; сверяй остальные фильтры и источник. Параметр вида — только экземпляра копии, не VIEW_NAME.
- Схема спецификаций 2×5: номера отдельных строк 1–10, правый столбец первым. Правый верхний видимый угол таблицы — на 5 мм ниже правого верхнего угла внутренней рамки (10 мм от верха бумаги, 5 мм справа), вертикальный зазор 0, горизонтальный вводится отдельно. Убирай невидимый API-отступ таблицы 1/12 дюйма при измерении. Размеры — по реальным таблицам после Regenerate. Резервируй занятую правую полосу для компоновки видов; выход в зону штампа/за лист сообщай, не удаляй копии из-за нехватки места. Ошибка одной спецификации не отменяет остальные.
- JSON версии 5 сохраняет источники, режим копирования, строку/условие фильтра, параметр экземпляра, схему и зазор. Ссылки в другом проекте сверяй по именам до изменения формы. Native Duplicate/SetFilter/Create и реальную компоновку проверяет пользователь в Revit.

- Все листы имеют поля бумаги: слева 20 мм, справа/сверху/снизу 5 мм. Общая геометрия — Common/SheetMargins.cs. Введённые отступы видов дополнительны к рамке; спецификации идут от её правого верхнего угла. Нижний резерв основной надписи 55 мм отсчитывается внутрь рамки.
